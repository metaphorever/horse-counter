## Decisions made

- **Post text goes info-only; the poem lives entirely in the image** — *confirmed*
  (Clover). Bluesky's `AppBskyFeedPost.Record` has a single `embed` field whose union has
  no "external card + images" variant, so attaching an image costs the 2.3 link card that
  was carrying the permalink for free. Clover's call: stop competing for budget — text
  becomes header + permalink + hashtags (~100 of 300 chars), poem goes in the picture.
  Simplification, not a cost: `_compose_body`'s truncation machinery leaves the critical
  path and stays as the failure fallback.
- **Alt text becomes mandatory** — falls directly out of the above. With the poem only in
  pixels, alt text is the sole text-accessible copy. 2.3 deferred alt text to "when image
  cards return"; this is that moment.
- **JPEG at ~85, not PNG** — *confirmed* (Clover). Bluesky's blob ceiling is ~1MB and a
  full-colour PNG of a Fancy poem exceeds it. Playwright emits JPEG directly, so no Pillow.
- **Variable height, capped** — *confirmed* (Clover, chosen from three options). Short
  poems stay punchy, horses stay legible at one chip size, only long poems clip.
  Truncation is *measured* (`scrollHeight` vs `clientHeight` via one `page.evaluate`),
  never assumed — CSS can clip but cannot report that it clipped.
- **Public-only, rendered at publish** — *confirmed* (Clover said public-only; render-at-
  publish is the refinement). Creation-time rendering would burn Chromium launches on
  submissions that are never approved. Two of the three `published` transitions already
  call `enqueue_crosspost` (`app.py:1759`, `app.py:2606`) — the hook is already there.
- **Pre-rendered static files** — *confirmed* (Clover). `data/cards/<short>.jpg`, gitignored,
  regenerable. This also makes `og:image` free (no crawler-triggered render path).
- **Phase 2.7, taken ahead of 2.5.1** — *confirmed* (Clover: pose variation is a bigger art
  lift than there's time for right now).

### Claude pushed back twice; one landed, one was overturned

1. **Persistent browser vs launch-per-render — Claude's pushback held.** Clover's instinct
   was to reuse one Playwright across requests in short succession to avoid a resource
   trap. The intuition inverts here: a persistent browser is ~200MB resident *permanently*
   × 2 gunicorn worker processes ≈ 400MB idle, whereas launch-per-render is ~1–2s startup
   and **zero** idle. At 1–2 poems/day the idle cost is the only one that matters. Spec'd
   as launch-per-render under a cross-process `fcntl` lock (a `threading.Lock` is
   insufficient — workers are separate processes).
2. **Dedicated card surface vs the permalink — Clover was right, Claude's framing was
   wrong.** Claude initially argued for a dedicated template to avoid coupling the card to
   the surface Phase 2.5 is about to animate. Clover pushed back: the animation work ships
   a no-animation setting, and a second template is a second renderer — exactly what 1.29
   eliminated. Steelman conceded. The real split isn't permalink-vs-template, it's **chips
   (share) vs chrome (don't)**: the card reuses `render_poem`/`render_chip` from
   `macros.html` like four other templates already do, and simply doesn't inherit nav,
   footer, tag sections, the admin tag editor, or popover JS. One renderer, second layout
   frame — which answers both concerns at once.

## The architectural trap, named

The obvious implementation — `page.goto('https://poet.horse/p/<code>')` — **deadlocks the
site**. Gunicorn runs 2 sync workers; an admin request blocked in Playwright holds worker A
while the headless browser's page load needs worker B. One render survives; two concurrent
renders, or a render plus any other slow request, hangs poet.horse. It also can't see
unpublished poems (visibility gate, `app.py:2287`).

Spec'd instead: render the HTML **in-process** (`render_template`) and serve it to the
browser via `page.route` interception against a fake origin — fulfil `/` with the HTML,
fulfil `/static/**` from disk, **abort everything else** so the card can never fetch from
the internet or hang on a third-party host.

## Sequencing: 2.7 before 2.5.1

Clover asked whether doing this now interferes with poses/animation later. It doesn't —
the card reuses the shared macros, so 2.5's sprite rework flows through automatically, and
cards are frozen files that a later art change cannot retroactively break.

**The one thing 2.7 must build for 2.5's sake is the regeneration path**
(`CARD_ART_VERSION` column + `POST /admin/cards/rebuild-stale`). Cheap now, genuinely
annoying to retrofit — without it, every future art change strands the entire back
catalogue at the old look. Called out in both the spec and the ROADMAP entry.

## Uncertainty flags

- **atproto alt-text ceiling (~2000?) and `AspectRatio` model shape** · resolved by
  checking the installed version before writing embed code. The 2.3 build already hit one
  of these (`send_post` had no `labels` param) — assume nothing about this library.
- **Tumblr `data64` over JSON** · `make_request` (`auth.py:130`) posts JSON only. Legacy
  `/post` `type=photo` should accept `data64` as a field, but this is untested. Contingency
  if rejected: multipart, which `make_request` can't do — would need a small dedicated
  upload function. Resolved by a `state='draft'` test post.
- **Chromium under gunicorn** · the 2026-06-18 smoke test launched from an interactive
  shell. Launching from inside the systemd user service with its own environment is a
  different test. Gate 4 in the spec.
- **`og:image` ratio wrinkle** · variable-height cards are right in-feed but wrong for OG
  (crawlers want ~1.91:1 and will letterbox or badly crop a tall card). Spec'd as a
  fixed-ratio 1200×630 variant clipped from the top of the same render — one extra
  `page.screenshot` with a `clip` rect, no second page load. Marked **droppable**.
