## What shipped (this PR)
1. **Safari shimmer sweep** (`static/horse-shimmer.js`, `static/style.css`).
   - **Root cause:** WebKit never repaints a SMIL `animateTransform` on a `linearGradient`'s `gradientTransform`. In Playwright WebKit 26.0 the frames are byte-identical over 1.8s with both the 2.5.1 script and the 2.4 script (`git show e494228:static/horse-shimmer.js`). Chromium differs every frame. So this is a 2.4 bug that was never checked in Safari. The 2.5.1 mask isn't the cause.
   - **Fix:** the mask sits on a still `<g>`. Inside it, a chip-wide `<rect class="hz-shine-band">` with a fixed bounding-box gradient slides from −100% to +100% of its own width (`transform-box: fill-box`, `@keyframes hz-sweep`, 2.6s linear). The band's geometry and timing match the old SMIL sweep. No SMIL is left.
   - **Also:** `prefers-reduced-motion` hides `.hz-shine` in CSS. The JS already bailed at load, so this only matters if the setting changes mid-visit.
2. **Print** (`static/print.css`, `static/style.css`).
   - `.poem-horse .hz-word` is forced to `#0f0c06`.
   - `* { text-shadow: none !important }` inside `@media print`. It's broader than the title and date line, on purpose: no on-grass shadow belongs on paper.
   - `.hz-shine` is hidden in print alongside `.hz`.
3. **Infinite Pasture scroll-loaded poses** (`app.py` `/pasture/more`, `templates/pasture.html`).
   - The route runs `assign_pose(h)` and adds `h['svg'] = horse_svg(h)` through `get_template_attribute`, so the macro stays the single source.
   - `chipHTML()` uses `h.svg` and falls back to the default-pose copy.
   - `/pasture/more` previously took `rev` from `horse_appearance()`. It now comes from `assign_pose()`, matching `/pasture`.

## Verification (local)
- **Shimmer:** a static page built from the real sprite, CSS and script, with 5 famous chips (mixed facing), in Playwright.
  - Before the fix: WebKit 1 distinct frame out of 4, Chromium 4 of 4.
  - After: both 4 of 4.
  - A contact sheet across both engines showed the band crossing the whole horse, clipped to the silhouette, mirrored chips included.
- **Print:** emulated print media in both engines. Title and attribution `text-shadow` read `none`, the name colour is `rgb(15,12,6)`, and `.hz` and `.hz-shine` are `display:none`. Screen values were unchanged.
- **Scroll poses:** Flask on :5055 with a scratch DB, `/pasture` scrolled four times in both engines.
  - WebKit: 150 scroll-loaded chips with 61 distinct poses. Chromium: 270 chips with 73 distinct poses.
  - Facing was mixed, there were 0 missing `<use>` refs and no page errors. The test client also returned `svg` on all 30 horses.
- **Not verified:** real Safari or a real iPhone. Playwright WebKit is close to Safari but not identical; that's the live hold.
- **No test suite** (per `spec/technical.md`). `py_compile` and a JS parse were clean.

## Decisions
- **Replace SMIL rather than hide the band in Safari.** *Claude.* The fallback the roadmap allowed ("hide the band there") wasn't needed once a CSS animation repainted correctly in WebKit. Browser-sniffing would have been the worse fix.
- **Print shadow reset is universal.** *Claude, low stakes.*
- **Scroll chips carry server-rendered SVG** rather than JS templating of pose names. *Claude.* It keeps one markup source, as the 2026-09-15 log suggested. It costs about 0.8KB per horse in the JSON.
