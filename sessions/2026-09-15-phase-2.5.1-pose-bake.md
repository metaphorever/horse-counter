## Decisions made
- **Name rides the bob, smoothly.** *Clover, confirmed from the harness picker.* Whole px was rejected: the text snaps while the body slides, so they drift apart.
- **The bob becomes a user toggle (2.5.2); no bob = the unpinned walk.** *Clover:* "looked fine to my eyes… that's the trade-off for the added readability." Logged in the overview, with the cost: two walk sets if both are offered.
- **Static haunch stays** (OQ1). *Clover:* "I don't think the hind looks stiff."
- **The harness bakes the sprite, not a new `tools/pose_horse.py`.** *Claude proposed; Clover confirmed in their own words:* "being able to test new edits and then publish all from the same place… if it was a script I would still be doing my visual check in the harness anyway." What it commits us to: rebuilding takes a browser and a click, and the posing logic lives in a prototype file. Bake's refusal checks are the guard against a broken sprite.
- **The server picks the pose; the shimmer follows the chip's pose.** *Clover confirmed* ("never trust the client lol").
- **Heads are baked, not rotated per chip, and the sprite carries the pose pool and weights.** *Claude; Clover didn't comment, so I proceeded (ok-level).*
  - **Complexity justification (pool in the sprite):** the server and the sprite must agree on pose ids. A pool read from the sprite can't name a pose that doesn't exist, and the weights live in one place.
- **Baked groups keep nested `rotate()` transforms** rather than flattened path data. *Claude.* That's the harness's own markup, and it's smaller.
- **Spacing values.** *Clover, tuned in devtools on the local build.* Claude split the grid's side spacing into `--hz-grid-col` (30px = the 18px grid gap plus Clover's 6px on each side), so poems and grids stop sharing a knob.
- **Phone line-height bump removed.** *Claude.* It was set when the desktop pitch was 5; it ended at 4, which is below 2.4's phone value of 4.2. That's a testing hold, below.
- **The fresh-DB init crash was out of scope and got spun off.** *Claude.* It's a pre-existing ordering bug: `apply_migrations()` runs before `ensure_crosspost_queue()`. Clover ran the task, which became PR #91; #92 came out of that session.
